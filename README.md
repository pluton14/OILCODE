# НефтеКод — МАС для управления производством ДТ

Рекомендательная система оператору: смотрит состояние процесса
АВТ → гидроочистка → блендинг, оценивает риск и ресурс катализатора, предлагает
изменение режима — либо обоснованно отказывается.

> **Данные хакатона в этот репозиторий не входят.** `docs/` — в `.gitignore`.
> Файлы остаются локально у каждого участника и сдаются организаторам
> отдельным каналом. Подробнее — «Данные» ниже.

## Запуск

```bash
pip install -r requirements.txt
python export_agent_inputs.py   # выгрузка данных для качества/надёжности
python run_demo.py              # скелет полного пайплайна (черновик, не финал)
```

Первый запуск разбирает xlsx в `cache/` — около минуты, дальше быстро.

## Структура проекта — четыре части

**1. База знаний** — все `.md` в корне (список выше).

**2. Агент данных — итоговый скрипт**, актуальная задача:
```
oilcode/config.py           карта тегов, рычаги, ограничения, реестры входов агентов
oilcode/contracts.py        dataclasses — граница между зонами ответственности
oilcode/data/loaders.py     чтение csv/xlsx, приведение к длинному формату
oilcode/agents/data.py      сам Агент данных — см. справку ниже
export_agent_inputs.py      точка входа: python export_agent_inputs.py
```

**3. Каркас демо** — черновой скелет полного пайплайна, не финальное решение:
```
oilcode/agents/{quality,reliability,optimization,blending}.py   заглушки
oilcode/orchestrator.py     разрешение конфликта целей
oilcode/report.py           печать рекомендации оператору (7 блоков)
run_demo.py                 точка входа: python run_demo.py
```

**4. Данные** — `docs/` и `cache/`, не в репозитории (см. ниже).

## Справка: Агент данных

Единственный агент, который читает сырые csv/xlsx. Закрывает шаги 1–2 цикла
ТЗ: получить состояние процесса, проверить его пригодность. Все остальные
агенты получают только его выход и не знают, что где-то на диске лежат
исходные файлы.

Два разных режима работы — не путать:

| Режим | Когда использовать | Что отдаёт |
|---|---|---|
| `DataAgent().build_state(ts)` | рантайм, один момент времени | `ProcessState` — снимок для оркестратора |
| `DataAgent().export_agent_datasets()` | обучение и проверка моделей | **готовые датасеты** — то, чем сейчас пользуются Агент качества и Агент надёжности |

### Ровно два файла (`python export_agent_inputs.py`)

Коллеги берут файл и работают — чистка уже сделана, повторять у себя не нужно.
Каждый файл — `.xlsx` с двумя листами: **«Данные»** (чистая таблица, без
единой лишней строки — открывается в Excel как обычная таблица) и
**«Справка»** (источник каждого тега и исключённые даты, отдельно, чтобы не
мешать данным). Третьего файла нет.

| Файл | Что внутри |
|---|---|
| `quality_agent_data.xlsx` | 15 тегов режима реактора и дизельного отбора АВТ + `sulfur_mg_kg`/`t95_c` (слиты из ЛИМС/ПАК, приоритет — самый свежий источник, с колонкой `*_source`) |
| `reliability_agent_data.xlsx` | 6 тегов износа: перепад давления, температуры слоя, водород |

Заглушки 307/251 уже заменены на пусто. Периоды простоя установки и первые
`STARTUP_BUFFER_HOURS` часов после пуска (мусор переходного режима — на
пуске 23.04.2024 сера скакнула до 2120 мг/кг) **уже занулены** в самих
значениях — не флагом, который надо не забыть применить, а фактическим NaN.
Список этих периодов — в шапке файла, вычислен из данных при каждом запуске.

### Через `ProcessState` (для рантайма)

| Поле | Что внутри |
|---|---|
| `kip` | значения тегов на момент времени — тот же список тегов, что и в CSV-выгрузке выше |
| `quality` | сера, Т95 и другие показатели: ЛИМС → ПАК по приоритету, с источником и возрастом каждого значения |
| `data_quality.unit_running` | `{"AVT": True, "24-2000": False}` — работает ли каждая установка отдельно |
| `data_quality.sentinels_found` | какие теги в этот момент показывают заглушку 307/251, а не измерение |
| `data_quality.overall` | `ok` / `degraded` / `insufficient` — **вердикт**, на который обязаны смотреть все остальные агенты до того, как что-либо считать |

**Право вето.** При `overall == "insufficient"` оркестратор отказывается,
не опрашивая остальных агентов.

**Что уже учтено:**
- экспорт даёт ровно два файла, не больше;
- источник тега и исключённые даты — на листе «Справка», включая простои
  гидроочистки в файле агента качества;
- известная остановка АВТ/ГО занулена в значениях, а не просто помечена;
- заглушки 307.00 и 251.00 отфильтровываются и не попадают как измерения;
- лабораторный результат недоступен раньше, чем через 4 часа после отбора
  пробы (запрет на утечку из будущего);
- плотность по ПАК не считается известной раньше 05.03.2025 (окно покрытия);
- порог свежести анализа свой у каждого показателя — `CetaneNumber` меряют
  раз в 29 суток, и общий порог 48 часов объявлял бы его устаревшим всегда.

**Как добавить агенту качества или надёжности новый тег:** дописать строку
в `config.QUALITY_AGENT_TAGS` или `config.RELIABILITY_AGENT_TAGS`
(`(тег, установка, физический смысл)`) — Агент данных подхватит его
автоматически, ничего в `agents/data.py` менять не нужно.

## Жёсткие правила

1. Спецификация — к **товарному продукту после блендинга**, не к выходу ГО.
2. Цель — минимальная стоимость, а не минимум серы. Переочистка это убыток.
3. Ничего из будущего. Метка ЛИМС — момент отбора, результат доступен на 4 ч позже.
4. Теги 24-2000 только через `config.tag_key()` — **8 имён пересекаются с АВТ**.
5. Заглушки `307.00` и `251.00` — не измерения, выбрасывать.
6. Отказ — валидный ответ.
