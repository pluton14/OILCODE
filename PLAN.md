# Порядок разработки

Сегодня 12.09, сдача ориентировочно 22.09 — **десять дней**.

Документ отвечает на два вопроса: **какой метод стоит внутри каждого
компонента** и **в каком порядке всё это строится четырьмя людьми**.

---

# ЧАСТЬ 1. Что и где мы используем

Это главная таблица. Метод выбран не «как модно», а под то, что показали
данные и что принято в отрасли.

| Компонент | Метод | Почему именно он |
|---|---|---|
| **Агент данных** | правила + статистический контроль | отказы известны поимённо: заглушки 307 и 251, три остановки, залипания, мёртвые теги. Правила здесь точнее и объяснимее модели |
| **Детектор аномалий** (доп. слой) | Isolation Forest или контрольные карты | для отказов, которых мы ещё не видели. ТЗ относит к «приветствуется» |
| **Виртуальный анализатор серы** | градиентный бустинг по телеметрии | нужен, когда **ПАК недоступен** — а ТЗ прямо предупреждает, что ПАК периодически выходит из строя |
| **Оценка серы сейчас и на 0–3 ч** | **инерция плюс поправка на действие** | проверено на данных: чистая инерция бьёт ML на горизонте 1 ч с разгромом и почти не уступает на 3 ч. Бороться с этим бессмысленно |
| **Эффект изменения режима (what-if)** | физическая зависимость, калиброванная по данным | из истории не восстанавливается: установка под управлением, оператор гасит возмущения. Организаторы это предусмотрели: «модель может быть достаточно простой, в т.ч. линейной» |
| **Агент надёжности** | тренд WABT внутри цикла + экстраполяция до предела | **стандартная отраслевая задача** (Fixed Bed Catalyst End-of-Run Prediction). Не самодельный прокси |
| **Агент оптимизации** | перебор по сетке | прозрачно и защитимо; апгрейд на Парето — если останется время |
| **Агент блендинга** | линейное программирование | задача линейна по построению; перебор как запасной вариант |
| **Оркестратор** | детерминированные правила | приоритет задан ТЗ; обязан давать одинаковый результат |
| **Объяснение оператору** | LLM с откатом на шаблон | организаторы: «слово в слово — не обязательно», но численные результаты обязаны совпадать |

## Что уже проверено и чего от этого ждать

| Проверка | Результат | Что это значит |
|---|---|---|
| Виртуальный анализатор по телеметрии | +7 % к предсказанию медианой | слабо, но это единственный вариант, когда ПАК молчит |
| Прогноз серы на 3 ч против инерции | +2.6 % | **агент качества нельзя продавать как «предсказатель серы»** |
| Прогноз серы на 1 ч против инерции | −33 % | инерция непобедима на коротком горизонте |
| Рост WABT внутри цикла | +0.95…+1.6 °C в месяц | деградация катализатора видна и измерима |
| Связь WABT с перепадом давления | +0.54…+0.59 | два независимых прибора показывают одно и то же |

**Главный вывод для позиционирования на защите.** Ценность системы не в
предсказании серы — там нас бьёт тривиальная инерция. Ценность в том, что
система **решает, что делать**: удерживает жёсткие ограничения, считает
экономику, следит за ресурсом катализатора и умеет отказаться.

# ЧАСТЬ 2. Порядок разработки

Принцип: **сначала контракты и заглушки, потом содержимое**. Тогда четыре
человека работают параллельно и ничего друг у друга не ломают, а сквозной
прогон существует с первого дня.

## Шаг 1. Синк и каркас — 13.09, полдня, все вместе

Принять решения из `PROTOTYPE.md` (раздел 9), затем зафиксировать:

- формат `ProcessState` и вердикта каждого агента;
- заглушку каждого агента, возвращающую правдоподобные числа;
- сквозной прогон `run_demo.py` на заглушках.

**Критерий готовности:** `python run_demo.py` печатает семь блоков. Внутри
пусто, но цепочка целая.

**Плюс обязательно в тот же день:** скрипт валидации с тремя базами сравнения
и зафиксированные метки — 230 превышений и спокойные периоды. См.
`VALIDATION.md`. Метрика пишется раньше модели, иначе «улучшили» будет
непроверяемым утверждением.

Без этого шага остальное делать нельзя — иначе четыре человека будут ждать
друг друга.

## Шаг 2. Параллельная разработка v0 — 14–16.09, три дня

Каждая зона делает **самую простую работающую версию**, не пытаясь сделать
хорошо.

### Зона 1. Данные

| Что | Критерий готовности |
|---|---|
| Загрузка и приведение всех файлов | четыре чистых таблицы |
| Фильтр заглушек 307 и 251, остановок, залипаний | список выброшенных точек с причиной |
| `ProcessState` с возрастом анализов и задержкой ЛИМС 4 ч | тест: ни одного значения из будущего |
| Отметка «данные пригодны / ограниченно / непригодны» | срабатывает на трёх остановках |

### Зона 2. Модели процесса

| Что | Критерий готовности |
|---|---|
| WABT из температур слоёв | график роста внутри цикла |
| Тренд деградации и запас до предела | «осталось N месяцев» с обоснованием |
| Оценка серы = инерция + поправка | сравнение с инерцией на отложенном периоде |
| Индекс тяжести режима и ограничение по температуре | ограничение уходит в оптимизатор |

### Зона 3. Решения

| Что | Критерий готовности |
|---|---|
| Перебор сценариев по рычагам с шагом | список вариантов с метриками |
| Жёсткие проверки отдельно от ранжирования | нарушивший выбывает, а не штрафуется |
| Блендинг: рецептура под спецификацию | доли в сумме 100 %, присадка ≤ 3 % |
| Спецификация как **входной параметр** | ужесточили — рекомендация изменилась |

### Зона 4. Сборка (капитан)

| Что | Критерий готовности |
|---|---|
| Оркестратор: порядок вето и разрешение конфликта | отказ срабатывает во всех трёх случаях |
| Семь блоков вывода | читается человеком |
| Каркас дашборда | показывает вердикты всех агентов |
| Сохранение прогонов | вход, оценки агентов, решение — на диск |

## Шаг 3. Первая интеграция — 17.09, один день

Заменяем заглушки на v0 по одной, **не все сразу**. После каждой замены
прогоняем сквозной тест.

**Критерий:** система проходит четыре обязательных сценария ТЗ — нормальный
период, риск, аномальные данные, полный цикл агентов.

Это контрольная точка. Если к 17.09 сквозной прогон не собрался — сокращаем
охват, а не догоняем.

## Шаг 4. Доведение — 18–20.09, три дня

Здесь и только здесь улучшаем модели:

- виртуальный анализатор серы на случай отказа ПАК;
- оценка неопределённости прогноза;
- детектор аномалий поверх правил;
- Парето вместо взвешенной суммы;
- дашборд до рабочего вида;
- LLM-объяснение с откатом на шаблон.

Всё из этого списка **необязательно**. Берём по одному, в порядке пользы для
защиты, и только если сквозной прогон устойчив.

## Шаг 5. Заморозка и защита — 21–22.09

- **21.09 — code freeze.** Никаких новых фич. Только README, тесты,
  воспроизводимость, демо-сценарии.
- Репетиция защиты вслух, целиком.
- Проверка на чистой машине: склонировали, поставили зависимости, запустили.
